# Бот із платними описами 33 позицій

Версія оновлення з меню позицій, оплатою Stars та збереженням покупок. Каталог містить 726 описів з підготовленого Word документа. Справжню оплату Telegram та розгортання на Railway потрібно перевірити перед увімкненням продажів. Ціни у Stars потребують окремого погодження.

## Що бачить користувач

Після введення дати бот надсилає схему та 33 кнопки у сітці, по шість у рядку. Telegram сам визначає форму й розмір кнопок. Закриті позиції позначені замочком, доступні лише номером. Кнопки 21 і 30 завжди безкоштовні. Після покупки замочок відповідної позиції зникає.

Одна покупка відкриває одну позицію лише для пари «Telegram акаунт + дата народження». Пакет відкриває всі позиції для цієї самої пари. Навіть якщо дві дати мають однаковий аркан, доступ не переноситься. П15 купується один раз і містить обидва результати. Повернення Stars відкликає доступ за відповідним платежем, зберігаючи інші чинні покупки.

Кнопка /purchases дозволяє повернутися до оплачених дат. Дані зберігаються в SQLite на постійному диску. Перезапуск або перевипуск контейнера не втрачає покупки, якщо постійний том залишається підключеним.

## Ціни

Побажання власниці: 50 грн за позицію та 1500 грн за весь портрет. Ці значення не перетворено на Stars автоматично.

Telegram вимагає оплату цифрових описів через Telegram Stars, валюта XTR. Рахунок не може фіксувати рівно 50 чи 1500 грн: вартість придбання Stars для покупця різниться за платформою, податками та способом покупки. Потрібно погодити дві цілі кількості Stars.

Змінні POSITION_PRICE_XTR і BUNDLE_PRICE_XTR навмисно порожні. До їх налаштування бот не надсилає рахунків і не приймає нових оплат; безкоштовні позиції працюють. Тестові числа у test_payments.py є лише тестовими даними, не комерційною пропозицією.

Пакет має окрему фіксовану ціну. Раніше сплачені окремі позиції автоматично її не зменшують. Це прямо зазначено в умовах перед покупкою. Підписок та автоматичних списань немає.

## Публічний GitHub і приватні описи

Наявний репозиторій Portret7997Bot залишається публічним. Платний каталог не слід публікувати у ньому. Інакше будь-хто зможе прочитати всі тексти без покупки.

У комплекті розгортання програмні файли відокремлені від private_content/positions.json. У GitHub завантажуються тільки програмні файли з nadia_bot. Каталог можна передати через приватні змінні Railway або окремо завантажити на Volume за шляхом /data/content/positions.json. Код підтримує каталог, стиснутий XZ і розділений між приватними змінними CATALOG_XZ_B64_1 та наступними. CATALOG_XZ_PARTS задає кількість частин, CATALOG_SHA256 перевіряє цілісність розпакованих даних. Ці значення не додаються до Git. Якщо таких змінних немає, бот шукає приватний файл на томі або поруч із кодом. Змінна CATALOG_PATH дозволяє вказати інше приватне розташування.

Файл content/positions.json також внесений до .gitignore. Вебзавантаження GitHub не застосовує .gitignore, тому не завантажуйте приватний файл вручну в публічний репозиторій.

## Встановлення на Railway

1. Підключити Railway та GitHub для оновлення наявного сервісу. Перевірити, що обрано наявний сервіс, а не новий бот.
2. У сервісі Portret7997Bot підключити постійний Volume з mount path /data. Залишити одну репліку, один регіон і один процес polling з цим токеном.
3. Зберегти поточний TELEGRAM_BOT_TOKEN у Railway Variables. У чат або код токен не вставляти.
4. Після згоди власниці передати приватні змінні каталогу. Альтернатива: завантажити приватний каталог на том як /data/content/positions.json. Через Railway CLI після вибору потрібного проєкту та сервісу: railway volume files upload ./private_content/positions.json /content/positions.json. У Volume шлях / відповідає кореню підключеного тому, не кореню контейнера. Також доступний railway volume browse / для керування файлами.
5. Оновити програмні файли репозиторію файлами nadia_bot. Dockerfile уже копіює нові модулі та папку content. У цій папці у публічному репозиторії має бути лише README, без платного JSON.
6. Встановити DATA_DIR=/data. RAILWAY_VOLUME_MOUNT_PATH Railway додає автоматично. Не підміняти її вручну: вона має відповідати реальному підключеному тому.
7. До погодження цін залишити POSITION_PRICE_XTR і BUNDLE_PRICE_XTR порожніми. Після погодження встановити цілі кількості Stars. Платний режим на Railway відмовиться запускатися без підключеного постійного тому.
8. Виконати Deploy і перевірити /start, дату, вільні кнопки 21 і 30, замочки інших позицій, /terms та /paysupport.
9. Перевірити Stars у тестовому середовищі Telegram. Використати окремого тестового бота і базу; не запускати другий polling процес з production токеном. Підключення до тестового середовища виконується через TELEGRAM_TEST_ENV=1 з окремим тестовим токеном. Після успішного тестування погодити ввімкнення production цін.
10. Увімкнути резервне копіювання Volume у Railway. Не видаляти том разом із перевипуском контейнера.

Програмі не потрібен HTTP порт чи публічний домен. Вона працює через long polling. Уже налаштований webhook автоматично не видаляється.

## Локальна перевірка

Потрібен Python 3.12. З кореня комплекту скопіювати приватний файл private_content/positions.json до nadia_bot/content/positions.json тільки локально. У папці nadia_bot виконати:

    python -m pip install -r requirements.txt
    python -m unittest -v

Для запуску скопіювати .env.example у .env, вписати токен та вказати DATA_DIR=./data. Ціни можна залишити порожніми. Запуск: python bot.py.

Тестування в цьому комплекті імітує Telegram API і не списує Stars. Формули перевірені попередніми прикладами; вони наведені окремо у FORMULAS_UA.md.

## Платежі та відновлення

Доступ з’являється лише після successful_payment. Попереднє погодження pre_checkout_query доступу не надає. Бот перевіряє власника рахунку, валюту, суму й сам рахунок у базі. Ідентифікатор платежу унікальний: повтор тієї самої події не створює повторної покупки. Сума та дата фіксуються при створенні рахунку, тож зміна вибраної дати не змінює вже виписаний рахунок.

Паралельна оплата для тієї самої дати тимчасово блокується. Якщо запізнілий платіж усе ж дублює вже відкритий доступ, він потрапляє на автоматичне повернення Stars. Невдала спроба повернення лишається в черзі для повтору. Вхідне повідомлення Telegram про повернення також відкликає доступ. Команди /terms, /support і /paysupport ведуть до @Lakshmi_775.

Підтверджена покупка записується до надсилання опису. Якщо Telegram недоступний під час доставки, доступ зберігається: користувач повертається через /purchases. При помилці запису в базу фінансова подія не підтверджується курсором і обробляється повторно.

Резервна копія із запущеного сервісу:

    python maintenance.py backup /data/backups/purchases.sqlite3

Для повного повернення конкретного платежу власник сервера використовує його telegram_payment_charge_id із журналу покупок:

    python maintenance.py refund PAYMENT_CHARGE_ID

Команда спочатку викликає refundStarPayment, потім відкликає відповідний доступ. Для відновлення резервної копії зупиніть бота, збережіть поточну базу, замініть purchases.sqlite3 копією та запустіть бота знову. Не копіюйте лише основний файл працюючої WAL бази звичайною файловою командою: використовуйте команду backup вище або резервні копії Volume.

## Службові дані

У базі: Telegram ID, дата, позиція або пакет, ціна Stars, час рахунку, версія прийнятих умов, ідентифікатори та стан платежів, курсор оновлень. Дати рахунків зберігаються і до оплати. Повідомлення користувачів, токени та дані карток не журналюються. База, резервні копії та .env виключені з Git і комплекту для завантаження.

## Персональні запрошення та місячний доступ

Позиції 21 і 30 безкоштовні для всіх. Персональне запрошення відкриває всі 33 позиції для необмеженої кількості дат в одному Telegram акаунті на один календарний місяць від підтвердження номера. Оплату продовження поки не підключено. Запланована вартість: 100 грн; цифровий доступ у Telegram потрібно продавати через Stars, ціну XTR ще не погоджено. Банківських платежів бот не приймає і не підтверджує.

1. Власник надсилає `/myid`. Числовий ID встановлюється в Railway як `BOT_OWNER_ID`. Без конфігурації адміністративні команди недоступні всім.
2. Власник надсилає `/invite +380XXXXXXXXX`. Дату народження в команді більше вказувати не потрібно.
3. Бот повертає посилання та команду `/revoke ID`. Посилання можна активувати протягом 7 днів; контактна перевірка діє 10 хвилин.
4. Отримувач відкриває посилання, натискає Start і «Поділитися своїм номером». Telegram контакт повинен належати відправнику та збігатися з номером у запрошенні. Введений текстом номер, чужий або пересланий контакт доступу не дають.
5. У момент підтвердження номера починається один календарний місяць доступу. Строк обчислюється за київським часом; наприклад, 19 жовтня о 12:00 до 19 листопада о 12:00. Для 31 січня кінцевим днем буде останній день лютого. `/access` показує строк.
6. Після завершення строку всі позиції, крім 21 і 30, знову закриті. На /start, /access, після розрахунку дати та при спробі відкрити закриту позицію користувач бачить повідомлення про продовження за 100 грн і те, що оплату ще не підключено. Автоматичних списань немає.

Повторне відкриття активованого посилання та інше запрошення для того самого акаунту не запускають новий безкоштовний місяць. `/cancel` скасовує поточну перевірку. `/revoke ID` скасовує запрошення та його місячний доступ. Раніше оплачені окремі позиції, якщо такі є, зберігають власні умови.

Раніше створені запрошення також переходять на місячний режим. Для вже активованих строк рахується від початкового моменту активації, а не від оновлення бота.

SQLite на постійному томі зберігає HMAC відбиток номера, SHA256 відбиток токена, строк доступу, автора та акаунт отримувача після активації. Ключ HMAC генерується один раз у базі. Номер і повне посилання в базі не зберігаються, проте можуть бути в історії чату Telegram. Копіюйте всю базу разом із state, не публікуйте її або резервні копії.

Перевірка номера працює на момент активації. Подальшу зміну номера або передачу Telegram акаунту бот не відстежує. Завершення або скасування доступу не видаляє вже надіслані описи з історії чату.
