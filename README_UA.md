# Бот із платними описами 33 позицій

Версія оновлення з меню позицій, оплатою Stars та збереженням покупок. Каталог містить 726 описів з підготовленого Word документа. Справжню оплату Telegram та розгортання на Railway потрібно перевірити перед увімкненням продажів. Ціни у Stars потребують окремого погодження.

## Що бачить користувач

Після введення дати бот надсилає схему та 33 кнопки у сітці, по шість у рядку. Telegram сам визначає форму й розмір кнопок. Закриті позиції позначені замочком, доступні лише номером. Кнопки 21 і 30 завжди безкоштовні. Після покупки замочок відповідної позиції зникає.

Одна покупка відкриває одну позицію лише для пари «Telegram акаунт + дата народження». Пакет відкриває всі позиції для цієї самої пари. Навіть якщо дві дати мають однаковий аркан, доступ не переноситься. П15 купується один раз і містить обидва результати. Повернення Stars відкликає доступ за відповідним платежем, зберігаючи інші чинні покупки.

Кнопка /purchases дозволяє повернутися до оплачених дат. Дані зберігаються в SQLite на постійному диску. Перезапуск або перевипуск контейнера не втрачає покупки, якщо постійний том залишається підключеним.

## Ціни

Побажання власниці: 50 грн за позицію та 1500 грн за весь портрет. Ці значення не перетворено на Stars автоматично.

Telegram вимагає оплату цифрових описів через Telegram Stars, валюта XTR. Рахунок не може фіксувати рівно 50 чи 1500 грн: вартість придбання Stars для покупця різниться за платформою, податками та способом покупки. Потрібно погодити дві цілі кількості Stars.

Змінні POSITION_PRICE_XTR і BUNDLE_PRICE_XTR навмисно порожні. До їх налаштування бот не надсилає рахунків і не приймає нових оплат; безкоштовні позиції працюють. Тестові числа у test_payments.py є лише тестовими даними, не комерційною пропозицією.

Пакет має окрему фіксовану ціну. Раніше сплачені окремі позиції автоматично її не зменшують. Це прямо зазначено в умовах перед покупкою. Підписок та автоматичних списань немає.

## Публічний GitHub і приватні описи

Наявний репозиторій Portret7997Bot залишається публічним. Платний каталог не слід публікувати у ньому. Інакше будь-хто зможе прочитати всі тексти без покупки.

У комплекті розгортання програмні файли відокремлені від private_content/positions.json. У GitHub завантажуються тільки програмні файли з nadia_bot. Каталог можна передати через приватні змінні Railway або окремо завантажити на Volume за шляхом /data/content/positions.json. Код підтримує каталог, стиснутий XZ і розділений між приватними змінними CATALOG_XZ_B64_1 та наступними. CATALOG_XZ_PARTS задає кількість частин, CATALOG_SHA256 перевіряє цілісність розпакованих даних. Ці значення не додаються до Git. Якщо таких змінних немає, бот шукає приватний файл на томі або поруч із кодом. Змінна CATALOG_PATH дозволяє вказати інше приватне розташування.

Файл content/positions.json також внесений до .gitignore. Вебзавантаження GitHub не застосовує .gitignore, тому не завантажуйте приватний файл вручну в публічний репозиторій.

## Встановлення на Railway

1. Підключити Railway та GitHub для оновлення наявного сервісу. Перевірити, що обрано наявний сервіс, а не новий бот.
2. У сервісі Portret7997Bot підключити постійний Volume з mount path /data. Залишити одну репліку, один регіон і один процес polling з цим токеном.
3. Зберегти поточний TELEGRAM_BOT_TOKEN у Railway Variables. У чат або код токен не вставляти.
4. Після згоди власниці передати приватні змінні каталогу. Альтернатива: завантажити приватний каталог на том як /data/content/positions.json. Через Railway CLI після вибору потрібного проєкту та сервісу: railway volume files upload ./private_content/positions.json /content/positions.json. У Volume шлях / відповідає кореню підключеного тому, не кореню контейнера. Також доступний railway volume browse / для керування файлами.
5. Оновити програмні файли репозиторію файлами nadia_bot. Dockerfile уже копіює нові модулі та папку content. У цій папці у публічному репозиторії має бути лише README, без платного JSON.
6. Встановити DATA_DIR=/data. RAILWAY_VOLUME_MOUNT_PATH Railway додає автоматично. Не підміняти її вручну: вона має відповідати реальному підключеному тому.
7. До погодження цін залишити POSITION_PRICE_XTR і BUNDLE_PRICE_XTR порожніми. Після погодження встановити цілі кількості Stars. Платний режим на Railway відмовиться запускатися без підключеного постійного тому.
8. Виконати Deploy і перевірити /start, дату, вільні кнопки 21 і 30, замочки інших позицій, /terms та /paysupport.
9. Перевірити Stars у тестовому середовищі Telegram. Використати окремого тестового бота і базу; не запускати другий polling процес з production токеном. Підключення до тестового середовища виконується через TELEGRAM_TEST_ENV=1 з окремим тестовим токеном. Після успішного тестування погодити ввімкнення production цін.
10. Увімкнути резервне копіювання Volume у Railway. Не видаляти том разом із перевипуском контейнера.

Програмі не потрібен HTTP порт чи публічний домен. Вона працює через long polling. Уже налаштований webhook автоматично не видаляється.

## Локальна перевірка

Потрібен Python 3.12. З кореня комплекту скопіювати приватний файл private_content/positions.json до nadia_bot/content/positions.json тільки локально. У папці nadia_bot виконати:

    python -m pip install -r requirements.txt
    python -m unittest -v

Для запуску скопіювати .env.example у .env, вписати токен та вказати DATA_DIR=./data. Ціни можна залишити порожніми. Запуск: python bot.py.

Тестування в цьому комплекті імітує Telegram API і не списує Stars. Формули перевірені попередніми прикладами; вони наведені окремо у FORMULAS_UA.md.

## Платежі та відновлення

Доступ з’являється лише після successful_payment. Попереднє погодження pre_checkout_query доступу не надає. Бот перевіряє власника рахунку, валюту, суму й сам рахунок у базі. Ідентифікатор платежу унікальний: повтор тієї самої події не створює повторної покупки. Сума та дата фіксуються при створенні рахунку, тож зміна вибраної дати не змінює вже виписаний рахунок.

Паралельна оплата для тієї самої дати тимчасово блокується. Якщо запізнілий платіж усе ж дублює вже відкритий доступ, він потрапляє на автоматичне повернення Stars. Невдала спроба повернення лишається в черзі для повтору. Вхідне повідомлення Telegram про повернення також відкликає доступ. Команди /terms, /support і /paysupport ведуть до @Lakshmi_775.

Підтверджена покупка записується до надсилання опису. Якщо Telegram недоступний під час доставки, доступ зберігається: користувач повертається через /purchases. При помилці запису в базу фінансова подія не підтверджується курсором і обробляється повторно.

Резервна копія із запущеного сервісу:

    python maintenance.py backup /data/backups/purchases.sqlite3

Для повного повернення конкретного платежу власник сервера використовує його telegram_payment_charge_id із журналу покупок:

    python maintenance.py refund PAYMENT_CHARGE_ID

Команда спочатку викликає refundStarPayment, потім відкликає відповідний доступ. Для відновлення резервної копії зупиніть бота, збережіть поточну базу, замініть purchases.sqlite3 копією та запустіть бота знову. Не копіюйте лише основний файл працюючої WAL бази звичайною файловою командою: використовуйте команду backup вище або резервні копії Volume.

## Службові дані

У базі: Telegram ID, дата, позиція або пакет, ціна Stars, час рахунку, версія прийнятих умов, ідентифікатори та стан платежів, курсор оновлень. Дати рахунків зберігаються і до оплати. Повідомлення користувачів, токени та дані карток не журналюються. База, резервні копії та .env виключені з Git і комплекту для завантаження.

## Персональні запрошення та ручне продовження

Позиції 21 і 30 безкоштовні для всіх. Запрошення відкриває всі 33 позиції для необмеженої кількості дат в одному Telegram акаунті на календарний місяць від підтвердження власного номера. Оплати та автоматичних списань за продовження в боті немає.

Власник визначається лише числовим `BOT_OWNER_ID` у Railway. Команди власника:

- `/invite +380XXXXXXXXX`: створити запрошення для номера Telegram, без дати народження. Активувати протягом 7 днів, перевірка контакту діє 10 хвилин.
- `/renew TELEGRAM_ID`: вручну додати один календарний місяць підтвердженому акаунту. Якщо доступ ще діє, місяць додається до його завершення; якщо закінчився, починається зараз. Команда не перевіряє оплату, власник самостійно перевіряє звернення. Повторна обробка того самого Telegram повідомлення не додає другий місяць. Нова команда окремим повідомленням додає ще місяць.
- `/revoke ID`: відкликати запрошення та весь наданий ним доступ, включно з ручними продовженнями. ID запрошення вказано у відповіді на /invite.

Отримувач спочатку відкриває посилання й підтверджує власний номер кнопкою Telegram. Чужий чи пересланий контакт не підходить. Посилання зберігає прив’язку до одного Telegram ID. Інше посилання не починає безкоштовний місяць заново. Новому, непідтвердженому або відкликаному акаунту /renew доступ не відкриває.

Після завершення місяця працює безкоштовний формат. /start, /access, меню та закриті позиції показують повідомлення: повний доступ коштує 100 грн на місяць, для продовження потрібно написати @Lakshmi_775. У тексті вказано власний Telegram ID отримувача, щоб власник міг застосувати /renew до потрібного акаунту. /myid також показує ID. Усі фінансові дії відбуваються поза ботом і не підтверджуються ним. Вимоги Telegram до цифрових продажів залишаються застосовними незалежно від ручного керування доступом.

`/access` показує точний строк за київським часом. Місяць рахується до того самого дня та часу наступного місяця; якщо такого дня немає, до останнього дня місяця. Автоматичних SMS, нагадувань або повідомлень іншим людям немає. Користувач бачить свій новий строк при наступному зверненні до бота.

SQLite на постійному томі зберігає відбитки номерів і токенів, прив’язку акаунту, строки та журнал продовжень з автором команди. Сам номер і повне посилання в базі не зберігаються, проте можуть залишатися в історії Telegram. Копіюйте всю базу зі state, не публікуйте її. Раніше оплачені окремі позиції зберігають власні умови. Уже надіслані тексти залишаються в чаті навіть після закриття доступу.

## Головне меню та нові розділи

`/start` або `/menu` відкриває головне меню. «Портрет 33П» запускає поточний портрет із введення дати; `/portrait` відкриває цей самий розділ напряму. Введення дати без вибору розділу також продовжує працювати для портрету.

Кнопки «Матриця», «Грошове призначення», «Соціальне призначення», «Прогноз на роки», «Прогноз на місяці» позначені «Незабаром». Вони пояснюють, що розрахунки ще не доступні; формул або описів цих розділів не додано. Місячні права доступу й безкоштовні позиції 21 та 30 збережено. Кнопка «Головне меню» є під портретом і в меню позицій.

## Розрахунок карми +/−

«Карма +/−» у головному меню та `/karma` тепер відкривають числовий розрахунок п’яти плюсових і п’яти мінусових позицій. Потрібен чинний повний місячний доступ. Після вибору розділу кожна введена дата рахується як карма, поки користувач не повернеться в головне меню, портрет або не надішле `/portrait`. Обраний розділ і остання коректна дата зберігаються окремо для кожного акаунту. Вибір іншого розділу одразу використовує поточну дату.

Формули з фото та уточнення автора задокументовані у FORMULAS_UA.md. Для плюсової та мінусової карми готові по 22 описи. Матриця, призначення та прогнози залишаються у планах.

Результат карми надсилається PNG з білим фоном: заголовок «Карма», верхній рядок «+» з п’ятьма позиціями та нижній «−» з п’ятьма позиціями у тому самому порядку. Дата є в підписі. Кнопки завантаження PNG прибрано з нових результатів карми й портрету.


## Поточна дата та квадратний портрет

Одна коректно введена дата зберігається в state для Telegram ID користувача. Кнопки «Портрет 33П» та «Карма +/−» одразу обчислюють результат за нею; повторне введення не потрібне. Нова коректна дата замінює поточну для всіх розділів. Некоректний текст або дата не стирають попередню. Дата переживає перезапуск, не передається іншим акаунтам і не відкриває доступу без чинних прав. Матриця, призначення й прогнози поки позначені як майбутні, але показують поточну дату.

Кнопки навігації та описів позицій у попередніх повідомленнях також використовують нову поточну дату. Історичні рахунки зберігають первинну дату покупки. `/forgetdate` видаляє поточну дату, не змінюючи історію повідомлень та покупок. Політика /privacy оновлена.

Портрет надсилається квадратним зображенням 2000×2000 з однаковими квадратними комірками та блакитними контурами. Розташування й лінії відповідають наданому фото IMG_2073(1).jpeg: П12 і П30 ліворуч, П7 праворуч із лінією до П8; нижня група A–F, G1/G2 праворуч, H, Кп і J внизу. Числа та формули не змінено.

## Пояснення під схемою портрету

Після схеми портрету бот показує короткі значення всіх 33 позицій із поля meaning каталогу. Сітка номерів та навігаційні кнопки розміщені лише після повного списку пояснень. Біля самого зображення кнопок немає. Якщо текст перевищує ліміт повідомлення Telegram, він ділиться на частини; клавіатура додається лише до останньої частини. Детальні описи арканів надалі відкриваються за номером із перевіркою прав доступу.

## Описи мінусової карми

Під схемою карми є п’ять кнопок «Мінус 1» ... «Мінус 5» з розрахованими арканами. Натискання показує погоджений опис відповідного аркану: тему, можливі труднощі, блоки, сильні сторони та контакт автора. Перед читанням каталогу кожне натискання перевіряє чинний місячний доступ. Старі кнопки використовують поточну дату акаунту й заново обчислюють аркан. Позиції можуть мати однакові аркани; кожна залишається окремою кнопкою.

Тексти приватні: їх не можна додавати до цього публічного репозиторію. У production вони читаються з KARMA_MINUS_XZ_PARTS, KARMA_MINUS_XZ_B64_1 ... N та KARMA_MINUS_SHA256. Це JSON з 22 записами, стиснений XZ і закодований base64, з перевіркою SHA256 вихідного JSON. Альтернатива: /data/content/karma_minus.json або KARMA_MINUS_PATH. Файл content/karma_minus.json призначений тільки для локальної роботи та виключений із Git. Каталог завантажується після перевірки доступу й кешується в межах процесу. Після оновлення змінних потрібен новий deployment. Тексти є символічними інтерпретаціями, без встановлення фактів про минулі життя чи медичних висновків.

## Описи плюсової карми

Під схемою спочатку розташовані п’ять кнопок «Плюс 1» ... «Плюс 5», потім п’ять мінусових позицій. Кожна показує відповідний розрахований аркан. Плюсові описи містять ресурс, можливі прояви, те, що може послаблювати ресурс, та контакт автора. Перевірка членства й поточної дати однакова для обох типів карми. Після завершення чи відкликання доступу старі кнопки не відкривають текстів.

Приватний каталог плюсової карми передається окремо через KARMA_PLUS_XZ_PARTS, KARMA_PLUS_XZ_B64_1 ... N та KARMA_PLUS_SHA256 з тією самою перевіркою цілісності. Альтернатива: /data/content/karma_positive.json або KARMA_PLUS_PATH. Файл content/karma_positive.json виключено з Git; публікувати його в репозиторії не можна. Після оновлення каталогу потрібен новий deployment. Тексти відповідають погодженому документу автора й не обіцяють здоров’я, доходу чи конкретних життєвих подій.

## Соціальне призначення

Кнопка «Соціальне призначення» та /social показують числовий результат під час чинного місячного доступу. Складаються всі цифри повної дати народження без попереднього зведення дня або року. Результат зводиться відніманням 22 до діапазону 1–22; 22 залишається 22. Для 16.09.1998 сума 43, результат 21. Для 28.11.1999 сума 40, результат 18.

Розділ використовує спільну поточну дату акаунту. Нова дата перераховує саме обраний розділ; переключення на портрет або карму використовує її ж. Обраний розділ переживає перезапуск. Доступ перевіряється перед кожним результатом. Описи арканів соціального призначення ще готуються й не підміняються описами портрету чи карми.
